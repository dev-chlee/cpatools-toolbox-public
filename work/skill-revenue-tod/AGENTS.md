# 매출 TOD

## 절대 어기지 않는 것

1. 공개는 허브(cpa-skills)의 공개 명령으로만 한다. 스킬 저장소와 허브는 언제나 private 이며 public 으로 바꾸지 않는다.
2. 고객 자료·자격증명을 커밋하지 않는다. 실제 재무제표, 감사조서, 실명 회사 정보, `.env`, 키 파일. private 저장소도 안전 보관이 아니다.
3. 회사·거래처·계정과목이 바뀌면 깨지는 규칙을 코드에 넣지 않는다. 그런 규칙은 문서에 둔다.
4. 확인하지 않은 것을 확인한 것처럼 집계하지 않는다. 계산 실패·미계산·보류를 정상으로 세지 않고, 산출물에 '통과'라고 쓰지 않는다.
5. 실자료와 산출물은 저장소 밖 보관소 `<루트>/<스킬 폴더명>/{input,work,output,logs}` 에만 둔다. 자리는 실행 옵션 > 환경변수 `CPA_SKILLS_STORAGE`(루트) > `~/cpa-skills-data` 순서로 정하고, 경로 해석은 허브 틀 `cpa_storage.py` 의 사본으로 한다. 코드에 이 PC 전용 경로를 넣지 않고, git 저장소 안에는 쓰지 않는다.

공통 규범 전문은 허브 저장소(cpa-skills)의 `docs/` 에 있다. 이 저장소에서는 허브 문서를 고치지 않는다.

## 이 스킬이 맡는 것

샘플링된 매출 리스트와 샘플별 증빙 텍스트를 받아, 매출유형별 검증 프로파일에 따라
증빙을 판독하고 상세 워크페이퍼(엑셀)를 만든다.

- `references/` — 판단 루브릭. 무엇을 증빙으로 인정하고 무엇을 미비로 볼지 정한다.
  **이것이 판단 기준의 원본이다.**
- `scripts/profiles.py` — 매출유형별(해외·국내·용역) 검증 프로파일.
- `scripts/` 나머지 — 파일 준비, 샘플 매핑 검증, 판정 계약 검증, 엑셀 생성.
- `scripts/cpa_storage.py` — 보관소 경로 해석. 허브 틀 원본의 사본이라 여기서 고치지 않는다(허브 `check` 가 대조).
- `_local/` — 옛 실데이터 드롭 위치. 지금은 보관소 안내(`_local/README.md`)만 있다. 공개 미러에서 제외된다.

## 맡지 않는 것

- **증빙 판독 자체.** 문서를 읽고 판정하는 것은 실행하는 LLM 이 한다. 코드는 그
  판정이 계약을 지켰는지 검증하고 결과를 엑셀로 만든다.
- OCR. 증빙은 이미 텍스트로 추출된 상태로 들어온다.
- 샘플링. 어떤 거래를 뽑을지는 이 스킬 밖에서 정해진다.

## 반드시 지켜지는 것

- **문서를 읽는 판단은 LLM, 그 밖은 결정형.** 이 경계를 흐리지 않는다. 증빙 인정
  여부를 코드의 문자열 매칭으로 대체하면 실데이터에서 깨진다.
- **증빙 게이트를 우회하는 경로를 만들지 않는다.** 증빙이 없거나 불충분한 샘플이
  검증 완료로 집계되면 안 된다.
- **매출유형별 프로파일이 다르다.** 해외매출과 국내매출에 같은 증빙 요건을 적용하지
  않는다. 프로파일을 추가할 때 기존 프로파일의 요건을 재사용하지 말고 그 유형에
  필요한 것을 새로 정한다.
- 미비·보류로 판정한 샘플의 사유가 결과에 남는다. 건수만 세고 사유를 버리지 않는다.

## 의존과 환경

외부 서비스나 시스템 도구에 의존하지 않는다. 입력 파일과 이 폴더의 파이썬 의존성만 있으면
돈다. 한 외부 의존이 끊겨도 다른 스킬이 도는 것과 같은 이유로, 이 스킬은 아무 데도 기대지 않는다.

## 테스트

```bash
uv run --no-project --with-requirements requirements.lock --with pytest python -m pytest tests -q -p no:cacheprovider
```

현재 **76건 통과** (2026-09-25 실측). `tests/conftest.py` 가 테스트마다 `CPA_SKILLS_STORAGE` 를 임시 폴더로 돌린다 — 테스트가 실제 보관소에 쓰지 않게.

테스트 파일이 검증 영역을 나눈다 — 증빙 게이트, 샘플 매핑, 대화 워크플로, 단위.
프로파일을 고치면 증빙 게이트 테스트를, 입력 형식을 고치면 샘플 매핑 테스트를 함께 본다.

무엇을 테스트해야 하는가: 판정의 정답을 고정하지 않는다. 검증하는 것은 계약이다 —
필수 필드가 채워졌는가, 증빙 없는 샘플이 통과로 집계되지 않는가, 엑셀 시트가 예상
구조로 나오는가.

## 공개 상태

공개 여부는 허브(cpa-skills)의 `config/publishing.yml` 이 정한다 — 이 저장소에는 적지 않는다. 공개되면 이 폴더의 파일이 공개 미러를 거쳐 사이트에 나가므로, 늘 아래를 지킨다.

- 문서와 코드에 운영자 절대경로·호스트 이름·단축 커맨드 표기를 쓰지 않는다.
- 예시 데이터에 실제 거래처명·실제 금액을 넣지 않는다.
- `requirements.txt` 를 유지한다. `.lock` 과 `.in` 은 공개되지 않는다.
- 공개 주소는 **폴더명**(`skill-revenue-tod`)을 그대로 쓴다. 폴더명을 바꾸면 이미 공개된
  링크가 깨진다. frontmatter 의 `name`(`revenue-tod`)과는 다른 값이다.
