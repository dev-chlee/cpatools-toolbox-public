# 레이아웃 보존 OCR

## 절대 어기지 않는 것

1. 공개는 허브(cpa-skills)의 공개 명령으로만 한다. 스킬 저장소와 허브는 언제나 private 이며 public 으로 바꾸지 않는다.
2. 고객 자료·자격증명을 커밋하지 않는다. 실제 재무제표, 감사조서, 실명 회사 정보, `.env`, 키 파일. private 저장소도 안전 보관이 아니다.
3. 회사·거래처·계정과목이 바뀌면 깨지는 규칙을 코드에 넣지 않는다. 그런 규칙은 문서에 둔다.
4. 확인하지 않은 것을 확인한 것처럼 집계하지 않는다. 계산 실패·미계산·보류를 정상으로 세지 않고, 산출물에 '통과'라고 쓰지 않는다.
5. 실자료와 산출물은 저장소 밖 보관소 `<루트>/<스킬 폴더명>/{input,work,output,logs}` 에만 둔다. 자리는 실행 옵션 > 환경변수 `CPA_SKILLS_STORAGE`(루트) > `~/cpa-skills-data` 순서로 정하고, 경로 해석은 허브 틀 `cpa_storage.py` 의 사본으로 한다. 코드에 이 PC 전용 경로를 넣지 않고, git 저장소 안에는 쓰지 않는다.

공통 규범 전문은 허브 저장소(cpa-skills)의 `docs/` 에 있다. 이 저장소에서는 허브 문서를 고치지 않는다.

## 이 스킬이 맡는 것

Google Document AI Layout Parser 로 PDF 를 배치 처리해, 레이아웃과 표 구조를 보존한
HTML·Markdown 으로 변환한다.

- `src/` — 변환 파이프라인.
- `src/cpa_storage.py` — 보관소 경로 해석. 허브 틀 원본의 사본이라 여기서 고치지 않는다(허브 `check` 가 대조).
- `scripts/` — 초기화와 배치 실행 진입점.
- `references/` — 선택 로드 문서. 트러블슈팅과 문서 유형별 판독 기준.
- 의존성 관리가 다른 스킬과 다르다 — `pyproject.toml` + `uv.lock` 을 쓴다.

## 맡지 않는 것

- **등기부의 근저당 합계·공동담보 분석.** 이 스킬은 취소선 존재 여부를 판별하고
  판독 범위를 정하는 데까지다. 담보 금액 산출은 등기부 분석 스킬의 몫이다.
- 다른 OCR 엔진. Upstage 기반 처리는 별도 스킬이다.
- 변환 결과의 회계적 해석.

## 반드시 지켜지는 것

- **등기부를 다룰 때는 이미지에서 취소선 존재를 먼저 확인한다.** 존재하거나 불확실하면
  상세 범위 판독으로 가고, 없다고 확인된 경우에만 텍스트 분석으로 넘어간다. 순서를
  바꾸면 말소된 항목이 현행으로 읽힌다.
- **배치는 파일 단위로 독립이다.** 한 PDF 실패가 배치를 중단시키지 않고, 끝에 성공·실패
  요약이 나온다.
- **표 구조를 잃은 변환 결과를 성공으로 처리하지 않는다.** 레이아웃 보존이 이 스킬의
  존재 이유이므로, 구조가 무너진 결과는 실패로 남긴다.
- **원문 텍스트가 빠지거나 페이지가 어긋난 변환 결과를 성공으로 처리하지 않는다.** 변환 직후
  원응답과 대조해 한 블록이라도 빠지거나 원래 페이지가 아닌 곳에 놓이면 검증 실패(종료 코드 3)로
  남긴다. 부모 블록의 텍스트는 자식 텍스트의 합이 아니므로, 부모 텍스트 유무로 자식 출력을
  건너뛰지 않는다.
- 자격증명 파일은 워크스페이스 밖에 두고 경로만 환경변수로 받는다. 변수 이름은
  `SKILL.md` 에 있다.

## 의존과 환경

| 필요한 것 | 없으면 |
|---|---|
| Google Document AI 자격증명과 프로세서 설정 | **초기화 단계에서 멈춘다.** 변수 이름은 `SKILL.md` 에 있다 |
| Google Document AI 서비스 | 이 스킬만 동작하지 않는다. 다른 스킬에는 영향이 없다 |

자격증명 파일은 워크스페이스 **밖**에 두고 경로만 환경변수로 넘긴다.

이 스킬만의 미해결과 함정은 `_notes/` 에 있다. 밑줄로 시작하는 폴더라 공개 미러에서 통째로 빠진다.

## 테스트

```bash
uv run python -m unittest discover -s tests -v
```

현재 **207건 모두 성공** (2026-09-25 실측). 테스트 setUp 이 `CPA_SKILLS_STORAGE` 를 임시 폴더로 돌린다 — 테스트가 실제 보관소에 쓰지 않게.

무엇을 테스트해야 하는가: 외부 API 를 실제로 부르지 않는 경로로 검증한다. 취소선
판별 분기를 고치면 존재·부재·불확실 세 갈래를 모두 넣는다 — 불확실 케이스가 존재
케이스로 합쳐지면 판독 범위가 줄어든다.

표 구조 검사를 고치면 병합 셀·표 안의 표·빈 칸 채움·칸 밀림을 합성 응답으로 검증한다. 검증기는 페이지
배정 항목과 원응답 블록을 위치 경로로 짝짓는다. 객체 동일성에 기대는 코드를 다시 들이지 않는다.

**MD 쪽 정규화는 출력기와 순서가 같아야 한다.** 출력기는 공백이 남아 있는 원문에 `|` 이스케이프를
걸므로, 검증기도 이스케이프를 먼저 풀고 공백을 나중에 뺀다(`verify.py` 의 `_md_value`). 순서를
뒤집으면 원문의 `\ `+`|` 가 이스케이프로 잘못 읽혀 멀쩡한 블록이 MD 누락으로 잡힌다. 텍스트 누락
검사와 표 구조 검사가 같은 함수를 쓰게 두고, 한쪽만 따로 정규화하지 않는다.

익스포터나 검증기를 고치면 합성 응답(`tests/layout_fixtures.py`)으로 누락·중복·페이지 배치를
검증한다. 최상위 블록 하나 아래에 본문 전체가 달린 응답, 부모와 자식이 모두 텍스트를 가진 응답,
여러 페이지에 걸친 표를 빠뜨리지 않는다. 실제 문서 응답은 고객 자료이므로 저장소에 넣지 않는다.

## 공개 상태

공개 여부는 허브(cpa-skills)의 `config/publishing.yml` 이 정한다 — 이 저장소에는 적지 않는다. 공개되면 이 폴더의 파일이 공개 미러를 거쳐 사이트에 나가므로, 늘 아래를 지킨다.

- 문서와 코드에 운영자 절대경로·호스트 이름·단축 커맨드 표기를 쓰지 않는다. 이
  스킬에는 호스트 단축 커맨드가 매핑돼 있으나, 그 표기를 이 폴더의 문서에 적으면
  공개 위생 검사가 막는다.
- 이 스킬은 `pyproject.toml` 로 설치된다. 미러 규칙상 `pyproject.toml` 은 나가지만
  `uv.lock` 은 나가지 않는다.
- `temp/` 와 `output/` 은 공개되지 않는다.
- 공개 주소는 **폴더명**(`skill-ocr-google-layout`)을 그대로 쓴다. 폴더명을 바꾸면 이미 공개된
  링크가 깨진다. frontmatter 의 `name`(`ocr-google-layout`)과는 다른 값이다.
