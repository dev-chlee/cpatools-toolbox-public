# 등기부 담보 분석

## 절대 어기지 않는 것

1. 공개는 허브(cpa-skills)의 공개 명령으로만 한다. 스킬 저장소와 허브는 언제나 private 이며 public 으로 바꾸지 않는다.
2. 고객 자료·자격증명을 커밋하지 않는다. 실제 재무제표, 감사조서, 실명 회사 정보, `.env`, 키 파일. private 저장소도 안전 보관이 아니다.
3. 회사·거래처·계정과목이 바뀌면 깨지는 규칙을 코드에 넣지 않는다. 그런 규칙은 문서에 둔다.
4. 확인하지 않은 것을 확인한 것처럼 집계하지 않는다. 계산 실패·미계산·보류를 정상으로 세지 않고, 산출물에 '통과'라고 쓰지 않는다.
5. 실자료와 산출물은 저장소 밖 보관소 `<루트>/<스킬 폴더명>/{input,work,output,logs}` 에만 둔다. 자리는 실행 옵션 > 환경변수 `CPA_SKILLS_STORAGE`(루트) > `~/cpa-skills-data` 순서로 정하고, 경로 해석은 허브 틀 `cpa_storage.py` 의 사본으로 한다. 코드에 이 PC 전용 경로를 넣지 않고, git 저장소 안에는 쓰지 않는다.

공통 규범 전문은 허브 저장소(cpa-skills)의 `docs/` 에 있다. 이 저장소에서는 허브 문서를 고치지 않는다.

## 이 스킬이 맡는 것

부동산등기부등본 PDF 를 읽어 현행 소유자·근저당·압류를 정리하고, 공동담보의 중복을
제거한 순 담보금액을 산출해 감사 조서(엑셀)로 만든다.

- `scripts/` — PDF 페이지 이미지화, 취소 범위 반영, 공동담보 중복 제거, 엑셀 생성.
- `references/` — 등기부 서식과 판독 기준.
- `examples/` — 공개 가능한 예시.
- `scripts/cpa_storage.py` — 보관소 경로 판정. 허브 틀 원본의 사본이라 여기서 고치지 않는다(허브 `check` 가 대조). 출력을 쓰는 CLI 가 인자 처리 직후 `guard` 로 git 저장소 안 출력 경로를 거부한다.
- `_local/` — 옛 실데이터 드롭 위치. 지금은 보관소 안내(`_local/README.md`)만 있다. `_` 로 시작하므로 공개 미러에서 통째로 제외된다.

## 맡지 않는 것

- **OCR 자체.** 텍스트 추출은 OCR 스킬의 몫이다. 이 스킬은 판독된 결과와 이미지를 쓴다.
- 등기부가 아닌 문서. 일반 PDF 분석 요청은 이 스킬의 범위가 아니다.
- 담보 적정성에 대한 회계적 판단. 금액을 산출할 뿐 충당금이나 손상 판단은 하지 않는다.

## 반드시 지켜지는 것

- **모든 페이지를 이미지로 확인한 뒤 분석한다.** 텍스트만 보고 결론 내리지 않는다.
  취소선이 그어진 항목을 텍스트에서 구분하지 못해 이미 말소된 근저당이 현행으로
  집계되는 것이 이 문서 유형의 대표적 오류다.
- **취소 범위가 불확실하면 확정하지 않는다.** 취소선 존재가 불확실한 경우 상세 판독을
  거치고, 그래도 불확실하면 결과에 그렇게 표시한다.
- **공동담보는 중복을 제거한 순액과 제거 전 총액을 함께 낸다.** 순액만 내면 검토자가
  제거 근거를 확인할 수 없다.
- 입력 PDF 를 수정하지 않는다.

## 의존과 환경

외부 서비스나 시스템 도구에 의존하지 않는다. 입력 파일과 이 폴더의 파이썬 의존성만 있으면
돈다. 한 외부 의존이 끊겨도 다른 스킬이 도는 것과 같은 이유로, 이 스킬은 아무 데도 기대지 않는다.

이 스킬만의 미해결과 함정은 `_notes/` 에 있다. 밑줄로 시작하는 폴더라 공개 미러에서 통째로 빠진다.

## 테스트

**pytest 로 수집하면 안 된다.** `tests/test_unit.py` 가 모듈 스코프에서 `sys.exit()` 를 부르고,
pytest 는 수집 단계에서 모듈을 import 하므로 그 시점에 프로세스가 죽는다. 자세한 것은
`_notes/engineering-notes.md` — 그 폴더는 공개되지 않으므로 여기 한 줄을 남겨 둔다.

```bash
uv run --no-project --with-requirements requirements.lock python tests/test_unit.py
uv run --no-project --with-requirements requirements.lock python tests/test_release.py -q
```

현재 **88 + 54 통과** (2026-09-25 실측). `test_release.py` 의 `StorageGuardTests` 가 출력 CLI 의 저장소 안 쓰기 거부를 본다. 단위 테스트 결과는
`tests/test_results_unit.json` 에 남는다(추적 파일 — 돌리면 줄바꿈이 바뀌므로 커밋 전에 되돌린다).

**위 두 커맨드가 `tests/` 전부는 아니다.** `test_complex_inputs.py` ·
`test_generalization.py` · `test_image_pipeline.py` · `test_image_review.py` 가 따로
있고, 그중 `test_image_pipeline.py` 는 판독 증거에서 CLI 를 거쳐 엑셀에 이르는
무결성을 대체 없이 검증한다 — `test_release.py` 자신이 그렇게 지목한다. 이미지
파이프라인이나 판독 경로를 고치면 이 파일을 반드시 함께 돌린다.

무엇을 테스트해야 하는가: 취소 범위 판정을 고치면 취소선이 있는 케이스와 없는 케이스를
모두 넣는다. 공동담보 로직을 고치면 물건이 셋 이상 얽힌 케이스를 포함한다 — 둘까지는
단순 차감으로도 맞아떨어져 회귀를 놓친다.

## 공개 상태

공개 여부는 허브(cpa-skills)의 `config/publishing.yml` 이 정한다 — 이 저장소에는 적지 않는다. 공개되면 이 폴더의 파일이 공개 미러를 거쳐 사이트에 나가므로, 늘 아래를 지킨다.

- 스킬 루트에 `.md` 를 새로 두면 그것도 공개된다.
- 문서와 코드에 운영자 절대경로·호스트 이름·단축 커맨드 표기를 쓰지 않는다. 쓰면
  공개 위생 검사가 막는다.
- `requirements.txt` 를 유지한다. `.lock` 과 `.in` 은 공개 미러로 나가지 않아, 이
  파일이 없으면 남이 클론했을 때 설치할 방법이 없다.
- 공개 주소는 **폴더명**(`skill-registry-mortgage-analysis`)을 그대로 쓴다. 폴더명을 바꾸면 이미 공개된
  링크가 깨진다. frontmatter 의 `name`(`registry-mortgage-analysis`)과는 다른 값이다.
