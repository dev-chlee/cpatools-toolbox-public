# 선택적 LLM 판단

이미지 판독은 항상 필수이고, 이 문서는 별도의 모호한 필드 판정에만 적용한다. 기본 절차는 [SKILL.md](../SKILL.md)를 따른다.


규칙 파싱이 확신하지 못한 필드가 있을 때만 사용한다. 아래는 Bash 줄 연결 예시다.
PowerShell에서는 각 명령을 한 줄로 합치고 설치한 venv의 Python을 사용한다. 3단계:

```bash
# ① 파싱 + 판단번들 생성 (규칙이 애매한 항목을 closed-set 후보와 함께 수집)
python scripts/parse_registry_pdfs.py <PDF폴더> <보관소>/output/registry --company <키워드> --emit-bundle \
    --image-review <보관소>/output/image-review/manifest.json
#    → <보관소>/output/registry_judgment_bundle.json  (항목 0건이면 여기서 종료 — LLM 불필요)

# ② LLM(에이전트) 판정 — 아래 '판단 루브릭'대로 verdict JSON 작성
#    → <보관소>/output/registry_verdicts.json

# ③ Python 확정 (무결성 검증 + guard 재검증 + 병합) → 워크페이퍼(Sheet6 증적 포함)
python scripts/apply_verdicts.py <보관소>/output/registry_judgment_bundle.json <보관소>/output/registry_verdicts.json \
    <보관소>/output/registry_properties.json <보관소>/output/registry_mortgages.json
python scripts/generate_workpaper.py <보관소>/output/registry_properties.final.json \
    <보관소>/output/registry_mortgages.final.json <보관소>/output/workpaper.xlsx \
    --company "주식회사예시" --period "2025년 기말감사" --company-keywords 예시 \
    --verdict-report <보관소>/output/registry_apply_report.json
```

### 원칙 (불변식)

- **LLM 은 closed-set 선택만**: 후보 '번호'로만 답한다. 자유문자열 제안 금지(환각 차단).
  `0`(소재지/소유자) / `[]`(공담) = "판단불가·현재값 유지" — **확신 없으면 반드시 이것**.
- **금액 산술은 100% Python**: 이미지 판독에서 원문 금액을 확인하며, 이 closed-set 판정 적용 단계에서는 금액 변경을 허용하지 않는다. dedup·Gross/Net 산술은 Python이 수행한다.
  공담 병합 제안도 Python guard(금액·권리자 일치 + 서술문-소재지 상호검증)를 통과해야만 반영.
- **재현성·보존**: **번들·verdict·apply_report 3개 JSON 을 워크페이퍼와 동일 조서 폴더에
  보존한다(전자조서 첨부물 — Sheet6 의 발췌는 절단본이며 번들해시 전문은 report 에 있다).**
  같은 verdict → 같은 조서 셀 값(`--as-of` 로 작성일 고정 가능). LLM 판단을 재실행하면 결과가
  달라질 수 있다 — 조서에 쓴 verdict 를 반드시 보관.
- **무결성**: verdict 는 번들해시로, 파싱 JSON 은 sha256 으로 번들에 바인딩된다. 파서 수정·재파싱·
  JSON 수기수정 후 구 verdict 재적용은 apply 가 거부한다 — 번들 재생성부터 다시.
  (선택적 판단번들의 입력 해시와 별개로, 이미지 완료 증거가 원본 PDF 및 판독 의존성을 다시 검증한다.)
- **LLM 병합 = Net 을 줄이는 판단**: 공담 병합 채택 건(Sheet4 식별방식 'LLM')은 확정 전 반드시
  ① 원본 을구의 공동담보/추가공동담보 기재, ② 금융조회서 담보 내역(설정 건수·채권최고액)과
  대사한다. **동일 은행·동일 금액이라도 별건 여신의 별개 근저당일 수 있다**(시설/운전자금 분리 등).
  apply 가 적용 전/후 Net 을 병기 출력하며, 대사 완료 전 조서에는 두 수치를 함께 표기한다.

### 판단 루브릭 (verdict 작성 규칙)

verdict JSON 형식: `{"메타": {"번들해시": <번들의 것>, "판단주체": "<모델ID>", "판단시각": "..."},
"판정": [{"판단ID": "J001", "선택": <번호|배열>, "근거": "...", "신뢰도": "high|med|low"}]}`

**소재지** (표제부 변경이력에서 현행 1개 선택):
- **번호 순서가 아니라 변경 사유의 시간 순서로 판단하라** — 합병·분할·등록전환·행정구역/지번변경·
  **환지(환지처분 포함)** 후의 표기가 현행이다. 환지는 지번이 전면 교체되므로 구 지번과의 유사성으로
  판단하지 마라. **전산이기·이기 행이 있으면 표시번호가 재시작될 수 있다 — 번호 크기 비교를 버려라.**
  건물 **멸실/신축** 흔적(멸실등기·신축 표기)이 보이면 신축 후 표기가 현행이며, 발급본에 구 건물
  표시가 남아 있어도 배제하라.
- **도로명주소 병기 행은 소재지 변경이 아니다.** '…에서 이기'/'분할로 인하여 …에' 문구의 지번은
  유래/이출 지번이지 이 물건의 현행 지번이 아니다.
- **발췌에는 취소선(말소 표시)이 보이지 않는다 — '말소 흔적이 없다'는 것은 현행의 근거가 아니다.**
  원본 이미지의 취소 범위와 후행 행의 변경 사유를 함께 확인하라. 후보의 출처가
  '표시번호 불명'이거나 발췌에 채권최고액·근저당권자 등 **을구 어휘가 섞여 있으면 을구 오염 후보다 —
  배제하라.**
- 어느 후보도 현행이라 확신할 수 없으면(후보에 현행 표기가 아예 없어 보이는 경우 포함) `0` + low 로
  답하고, 근거에 "후보 중 현행 없음 의심 — 현재값도 검증 필요"를 명기하라. **`0`은 '현재값이 옳다'는
  뜻이 아니라 '판단 불가'라는 뜻이며, 시스템이 검토필요로 플래그한다.** 잘못된 주소가 조서에 실리는
  것이 공란보다 나쁘다.

**공담** (서술이 지칭하는 상대 물건 선택, 복수 가능):
- 원문발췌의 '공동담보 토지/건물 〈소재지〉' 서술과 후보의 소재지가 **지번 단위로 일치**하는
  것만 골라라. 부분 일치(동/리만 같고 지번 다름)는 제외.
- 후보 중 확신할 것이 없으면 `[]`(세트 외/매칭 불가) — 상대 물건이 입력 폴더에 없는 경우
  (계열사·물상보증인 부동산)가 실제로 흔하다. 억지 매칭 금지.
- Python guard 가 금액·권리자·서술문을 재검증하므로, 네 판단이 틀려도 병합은 차단된다 —
  그래도 guard 를 믿고 느슨하게 고르지 마라.

**소유자** (본인 1/제3자 2):
- '본인' = 원문발췌 소유자명이 피감사회사 키워드와 상호 전체 수준에서 일치(표기 흔들림·법인격
  위치 차이는 허용, 예: '(주)X' vs 'X주식회사').
- 상호가 유사하기만 한 경우는 '본인'이 아니다 — `2`(제3자). **관계사 여부는 등기부만으로 확정할
  수 없으므로 자동 판정 대상이 아니다** — 감사팀이 관계사 리스트로 별도 대조한다.
- 단, 제3자로 판정하되 **소유자 상호에 피감사회사 상호의 어간·그룹명이 포함되거나 임원 성명 일치가
  의심되면 근거에 '관계사 의심'을 반드시 명기하라**(분류는 여전히 `2` — 라벨로 단정하지 않는다).
  시스템이 이를 특수관계자 대조 검토필요로 플래그한다.
- 확신 없으면 반드시 `0`(판단불가). 근거 없는 제3자 판정도 금지한다.

**신뢰도**: high = 원문에 명시적 근거, med = 정황 종합, low = 추정(→ Python 이 **미적용** 처리).
근거는 "원문의 무엇을 보고 판단했는지" 1문장 — Sheet6 에 그대로 실려 검토자가 재수행한다.
