# 분석 규칙·조서 구성·한계

기본 실행은 [SKILL.md](../SKILL.md)를 따른다. 금액·분류·조서 해석 또는 보류 원인을 확인할 때 읽는다.


### Phase 1: PDF 파싱 — 부동산 기본정보 + 소유권

각 PDF에서 다음을 추출한다:

**표제부**:
- 고유번호 (예: `XXXX-XXXX-XXXXXX`)
- 유형 (토지/건물/집합건물)
- 현행 소재지와 집합건물 동·층·호. 면적·지목·건물내역은 독립된 구조화 출력 필드가 아니다.

**갑구 (소유권)**:
- 현재소유자, 등록번호, 지분 (공유 시 각 소유자별)
- 순차 지분 일부이전 공유 인식: 마지막 소유권 등기가 '일부이전'이면 직전 등기의
  잔여 지분 보유자까지 현행 공유자로 합산
- 피감사회사 소유 여부 판정 (회사명에 피감사회사 관련 키워드 포함 여부)

**소유자·지분·집합건물 검토**:
- 요약표의 줄바꿈 법인명과 공유자 지분을 복원한다. 잔여 지분을 확정할 수 없거나 지분 합계가 1이 아니면 `소유자확인필요`로 남긴다. 회사 여부만 선택하는 LLM 판정으로 해제하지 않는다.
- 근저당의 `대상소유자목록`과 현재 소유자를 대조한다. 공유 부동산에 회사 지분이 있다는 이유로 다른 공유자의 근저당까지 회사 담보로 분류하지 않는다. 대상 미확정은 미상 축으로 남긴다.
- 설정일·접수번호는 해당 설정 행과 요약표의 동일 순위에서 읽으며 변경 부기의 접수일로 대체하지 않는다.
- 확인된 옛 상호도 회사 키워드에 포함할 수 있다. 원본의 상호변경·법인 식별정보로 동일 법인임을 확인하고 파서·엑셀에 같은 키워드를 전달한다.
- Sheet1은 해당 근저당의 담보 대상 소유자·지분, Sheet2는 부동산 전체 소유 현황을 나타낸다. Sheet5는 담보 대상 지분 기준이며 혼합 금액을 안분하지 않는다.
- 대지권 토지 주소로 집합건물 전유부분 주소를 대체하지 않는다. 공동담보 상대 물건의 동·층·호까지 대조한다.
- 소유권이전에 붙은 신탁등기말소만으로 소유권이전 자체를 취소하지 않는다. 수탁자 명의도 원본 소유 현황에 기록한다.

**소유자·가압류 판정 경로**:
- 소유자는 하단 "주요 등기사항 요약"이 있으면 요약 기준
- 요약이 없거나 요약이 소유자를 놓친 경우(법인명 조각 등) **갑구 표 기반**으로 폴백 —
  이 경우 `갑구_특이사항`에 "본문추정(수동확인 권장)" 플래그를 남긴다
- 압류/가압류는 갑구의 순위별 설정·말소·말소회복을 대조한다. 상세 이미지 판독의
  현행 순위·종류 목록 및 건수와 파싱 결과가 모두 일치해야 한다.

**기타 부담 키워드 감지** (`기타부담_감지`):
- 전세권·지상권·경매개시결정·신탁·가등기·환매특약 키워드의 존재를 감지해 플래그
- 상세 판독 대상은 취소·대체 범위를 제외한 현행본에서 감지한다. 취소선 없음 분기의
  텍스트는 후속 말소 기재와 원본을 대조한다. 기타부담의 법률상 효력을 자동 확정하지 않으며
  Sheet2 비고의 원본 확인 안내를 유지한다.

### Phase 2: 을구 — 현행 근저당 추출 (표 기반, 요약표 불필요)

**을구 표를 셀 단위로 읽어** `근저당권설정 − 근저당권설정등기말소 = 현행` 으로 산출한다
(pdfplumber `extract_tables`). 하단 요약은 근저당 추출에 사용하지 않는다(표 추출이 완전 실패한
경우의 안전 폴백만). 주요 규칙:

- **표 수집 격리**: 을구 시작 이후의 표만 수집하고, 하단 요약표('대상소유자' 헤더)·공동담보목록
  별지('일련번호' 헤더)는 제외 — 갑구/요약/별지 텍스트가 을구 순위에 오염되면 접수번호가
  갑구 등기 것으로 바뀌는 치명적 오류가 난다
- **말소 판정**: 'N번근저당권설정등기말소'의 대상 순위를 제외한다. 복수 순위 나열·범위와
  등기목적 반복 나열을 함께 처리한다. 말소회복은 원 설정을 되살리며, 말소청구 가처분·예고는
  취소로 처리하지 않는다. 원 설정이 없는 회복이나 불명확한 순위 범위는 보류한다.
- **지분근저당 인식**: '갑구N번 ○○지분(전부|일부)근저당권설정'도 현행 설정으로 집계하고
  `지분대상: true` 플래그(담보 목적물이 지분임을 표시). 채권최고액은 지분과 무관하게 전액
- **채권최고액 변경 부기 반영**: '근저당권변경'(감액/증액) 부기가 있으면 **마지막(변경 후)
  금액**이 현행 채권최고액. 설정 당시 금액은 `설정시채권최고액`에 보존
- **등기목적 정규화·워터마크 복원**: 다페이지 표에서 목적 셀에 '등 기 목 적' 헤더가 침투하거나
  ('…지분 등 기 목 적 전부근저당권설정'), '열람용' 워터마크가 토큰 안에 박히는('채용권최고액',
  '202열4년') 실서식을 정규화 후 매칭
- **근저당권자**: 등록번호 앵커 1차 + 금융기관 접미 경계 2차 폴백. 표 추출이 상호에 끼운 공백
  ('주식회사 경남은행')과 상호 속 지명('경남은행'의 '경남')을 주소로 오인하지 않도록 처리

### Phase 3: 공동담보 식별 (목록번호형 + 직접명시형)

공동담보는 서식이 두 가지다:

1. **목록번호형**: `공동담보목록 제YYYY-NNNN호` (부동산등기법 제78조). 법적 식별자 — 1차 그룹 키
2. **직접명시형**: 목록번호 없이 `공동담보 토지/건물 〈소재지〉` 로 상대 부동산을 직접 기재
   (등기소별 서식 편차). '공동담보' 뒤에 목적물(토지/건물/전세권/목록)이 오는 서식으로 감지 —
   '공동담보 일부 소멸' 류 부기만으로는 공담으로 오탐하지 않는다.
   공장저당('공장 및 광업재단 저당법 제6조 목록')도 공담 지표로 인정

**파싱 주의사항**:
- 담보추가(기존 근저당에 추가 부동산 편입): 접수번호는 다르지만 공동담보목록 번호는 동일
- 직접명시형의 상대 물건이 **입력 세트 밖**(계열사·물상보증인 부동산)이면 자동 병합 불가 —
  단독으로 계상되어 Net 이 과대일 수 있다(수동확인)
- **관할 등기소가 다른** 물건은 접수번호만으로 병합하지 않는다. 공통 목록 식별이 없으면
  별도 담보 관계 대조가 필요하다.

### Phase 4: 순 담보금액 산출

그룹핑 로직의 단일 SSOT 는 **`scripts/grouping.py`** 다 — 파서 미리보기와 워크페이퍼가 같은
모듈을 사용하므로 동일한 입력 JSON에서는 두 산출물의 Net이 일치한다. 선택적 판단으로
그룹이 변경되면 적용 전후 금액을 구별한다. 키 체계:

| 키 | 조건 | 의미 |
|---|---|---|
| `공동담보목록 제YYYY-NNNN호` | 목록번호 파싱됨 | 법적 식별자(최우선) |
| `llm_<판단ID>` | 선택적 판정의 Python guard 통과 | 목록번호가 없을 때 확정 병합 |
| `receipt_<등기소4>_<설정일자>_<접수번호>_<채권최고액>` | 직접명시형 공담 + 접수·일자 존재 | 같은 근저당은 전 물건에서 등기소·접수일·접수번호·금액이 동일 — 안전 병합 |
| `solo_<고유번호 또는 No>_<순위번호>` | 그 외(단독담보·식별 불가) | 물건·순위별 고유 키(오병합 방지) |

- 복수 설정의 접수 키에는 `_item1`, `_item2`처럼 항목번호를 붙여 같은 접수·금액의 별개 항목을 구분한다.
- 접수번호는 **등기소 내에서만 유일** → 등기소코드(고유번호 앞 4자리) 없이 병합하면 타 등기소의
  동일 접수번호와 오병합된다. 설정일자·채권최고액은 동일 근저당이면 반드시 같으므로 안전벨트
- 설정일자 미파싱 건은 receipt 병합을 포기하고 단독으로 강등(연도 불명 오병합 방지)
- `Net = Σ(그룹당 채권최고액 1회)`, `중복 = Gross − Net`

> 왜 이 방식인가: 동일 근저당이 10개 부동산에 공동담보로 설정되면 총 채권최고액은 ×10으로 과대계상된다. 그룹당 1회만 인정해야 실질 담보 한도가 나온다.

### Phase 5: 워크페이퍼 생성

openpyxl로 기본 5개 시트와 `이미지검토근거` 시트를 생성한다 (LLM 판단 경로 사용 시 `6_LLM판단근거` 추가).

#### Sheet 1: 근저당 상세

| 컬럼 | 내용 |
|------|------|
| No, 고유번호, 유형, 소재지 | 부동산 식별 |
| 소유자, 회사소유, 지분 | 소유 현황 |
| 순위번호, 설정일자, 접수정보 | 근저당 기본 |
| 채권최고액 | 금액 (숫자 형식) |
| 근저당권자, 채무자 | 당사자 |
| 공동담보목록, 공동담보구분, 공동담보 | 공동담보 상세 |

- 필수 식별값·금액과 원본을 대조한다. 해당 없는 공동담보목록 등 선택 항목은 공란일 수 있다.
- 피감사회사 소유: 파란, 피감사회사 공동소유: 진파란, 제3자: 노란, 분류 미상: 회색 배경

#### Sheet 2: 부동산 종합표

부동산별 1행으로 집계. 소유 현황, 근저당 건수/합계, 가압류 현황 포함.

#### Sheet 3: 요약

- 총 부동산 건수, 회사·제3자·미상별 건수. 소유자 분류 미상은 요약 상단에도 경고한다.
- 현행 근저당 건수, 채권최고액 합계
- 가압류 현존 여부
- 순 담보금액 (gross, 중복, net)
- 근저당권자별 집계
- 유의 문구(채권최고액≠실채무·자동화 범위) + LLM 판정 검토필요 경고(해당 시)

#### Sheet 4: 담보금액 분석

- Section A: 요약 (Gross → 중복제거 → Net)
- Section B: 공동담보 그룹별 순 담보금액 산출 내역 (금액 내림차순)
  - 그룹 식별자, 식별방식(목록/접수/단독), 근저당권자, 채무자
  - 건당 채권최고액, 대상물건수, Gross합계, 순담보금액, 중복제거액
  - 공동담보 그룹은 주황색 구분
- Section C: 공동담보 그룹 상세 전개 (2건 이상 그룹의 개별 물건)

#### Sheet 5: 물상보증 매트릭스

Net 단일 숫자는 성격이 정반대인 담보를 한 합계에 섞어 감사 판단을 오도한다. 이 시트가 Net 을
**소유(담보제공자) × 채무자** 로 분해한다.

| | 채무자 = 회사 | 채무자 = 제3자 |
|---|---|---|
| **소유 = 회사** | 자기담보 — 차입금 담보 주석과 대사 | **물상보증 제공** — 관련 약정과 적용 회계기준에 따라 주석 검토 |
| **소유 = 제3자** | **물상보증 수령** — 담보제공자의 특수관계자 여부 대조 | 회사 무관 — 검토 세트 편입 사유 확인 |

- **혼합 축**: 한 공동담보가 회사 물건과 제3자 물건에 함께 걸린 경우. 실데이터에서 물상보증이
  실제로 발생하는 지점이므로 '구분 불가'로 묻지 않고 **채무자축 기준으로 승격**해 표시한다
  (`혼합 — 회사채무` / `혼합 — 제3자채무`). 소유자·채무자가 미파싱이면 '미상'.
  회사 귀속 판단 근거(유효한 이름·회사 키워드 또는 확정 분류)가 없으면 제3자로 단정하지 않는다.
  그룹 구성원 중 미상이 하나라도 있으면 해당 축을 미상으로 두며, 확인된 회사+제3자만 혼합이다.
  LLM의 확정 분류는 파서 플래그·키워드보다 우선한다.
- **금액 안분 없음 (불변식)**: 그룹이 분면에 걸쳐도 금액을 쪼개지 않는다. 안분은 근거 없는
  숫자를 만들고, 그 숫자가 조서에 남으면 검토자가 실재하지 않는 배분을 사실로 읽는다.
  대신 그룹별 **회사물건/제3자물건/미상물건 건수**를 별도 열로 표시해 안분 없이 구성을 읽게 한다.
- **셀 합계 ≡ Net (불변식)**: 모든 그룹이 정확히 한 셀에 배정된다. 불일치하면 생성이 중단된다
  (조서가 조용히 틀리는 것보다 낫다). 시트에도 검증 라인이 인쇄된다.
- Section A 매트릭스 / Section B 구분별 해석·감사 조치 / Section C 그룹별 판정 내역.
- **물건수 ≠ 근저당건수**: 물건수는 고유번호(부동산) 기준, 근저당건수는 을구 항목 기준이다.
  한 물건이 여러 그룹에 걸리면 셀 간 물건수는 중복 계상된다(금액만 배타적으로 배정).

> 판정 규칙(회사귀속·축 분류)은 `scripts/guarantee_matrix.py` 가 단일 SSOT 다. Sheet1 의
> '회사소유' 표시도 같은 함수를 쓴다 — 두 벌로 갈라지면 표시와 매트릭스가 어긋난 조서가 된다.

#### Sheet 6: LLM 판단근거 (LLM 경로 사용 시에만)

`--verdict-report` 지정 시 추가. 상세는 [선택적 LLM 판단](llm-judgment.md)을 참조한다.

## 감사 관점 유의사항


- **채권최고액 ≠ 실채무**: 등기에 기재된 채권최고액은 실제 채무 잔액을 뜻하지 않는다. 주석 금액으로 직접
  인용하지 말고 금융조회서·차입금원장과 별도 대사한다(Sheet3 유의 문구 자동 표기).
- **자동화 범위**: 이 조서는 **근저당·(가)압류만** 자동 집계한다. 전세권·지상권(담보지상권)·
  경매개시결정·신탁·가등기·환매 등 기타 부담은 키워드 감지 플래그(Sheet2 비고)까지만 —
  감지되면 반드시 원본을 대조한다. 특히 **담보신탁**은 소유자가 수탁자 명의로 바뀌므로
  소유자 판정 자체를 재검토해야 한다.
- **물상보증 구분**: Sheet5 매트릭스가 Net 을 소유×채무자로 자동 분해한다(v0.5). **물상보증
  제공**(회사 자산 ← 제3자 채무)은 관련 약정과 적용 회계기준에 따른 검토 대상이고, **물상보증 수령**
  (제3자 자산 ← 회사 채무)은 담보제공자의 특수관계자 여부 대조 대상이다. 단 분해는 **공동담보
  그룹 단위**이고 금액 안분을 하지 않으므로, '혼합' 표시 그룹은 물건별 구분을 원본으로 확인한다.
- **특수관계자 대조(완전성)**: '제3자' 분류 물건 **전수**를 감사팀 관계사 리스트와 대조한다
  (특수관계자 담보·보증 주석 검토). Sheet5 의 '물상보증 제공'·'혼합 — 제3자채무' 행과
  Sheet6 근거의 '관계사 의심' 표기 건을 우선 확인.
- **가압류/압류**: 갑구의 순위별 현행 상태와 원본 이미지 판독 목록을 대조한다. 본문 취소선과
  후속 말소·말소회복을 함께 확인한다.
- **원본 수정 금지**: 회사제시 PDF 원본은 읽기 전용. 모든 결과는 별도 경로에 저장.

## 파싱 한계 및 수동 검증 가이드

검증한 자료에서 통과한 결과가 미지의 모든 서식에 대한 정확도를 보장하지는 않는다.
아래 항목은 원본 이미지와 대조하며 판독 불가·구조 손상·지원 범위 밖의 권리는 보류한다.

### 한계 1: 이미지 판독의 정확도

텍스트만으로는 PDF에 그려진 선 범위를 복원할 수 없다. 따라서 이 버전은 모든 PDF의 이미지를 확인하고 취소선이 있으면 상세 판독을 필수로 거친다. 흐린 선·부분 취소·다페이지 계속 행을 에이전트가 잘못 판단할 위험은 남는다. 불확실하면 보류하고 확대/원본 재확보로 확인한다. 기타부담은 현행본에서도 키워드 감지 범위이므로 법률상 효력 전반의 자동 판정은 아니다.

### 한계 2: 세트 외 / 타 등기소 공동담보 (Net 과대 방향)

직접명시형 공담의 상대 물건이 입력 폴더에 없거나(계열사·물상보증인 부동산) 관할 등기소가
다르면 자동 병합되지 않아 **Net 이 과대**일 수 있다. '외 N필지' 축약 서술은 guard 가 소재지
토큰 미등장으로 기각한다 — 동일 은행·금액·설정일의 단독 그룹이 병존하면 수동 병합 검토.
**검증**: Sheet4 에서 '접수/단독' 식별방식 그룹 중 채권최고액·근저당권자·설정일이 동일한
그룹이 여럿이면 동일 근저당 의심 — 원본의 공동담보 기재를 확인.

### 한계 2-2: LLM 병합 오류 (Net 과소 방향 — 감사상 더 위험)

LLM 공담 병합이 틀리면 **별개 근저당이 1건으로 합쳐져 담보 부담이 과소 표시**된다(누락 방향).
guard(금액·권리자·서술문 검증)가 걸러도, 동일 부지의 토지·건물에 같은 은행이 같은 금액으로
**별건** 근저당을 설정한 경우는 서술문 지번까지 일치해 통과할 수 있다.
**검증(필수)**: Sheet4 'LLM' 그룹 전건을 원본 을구 추가공동담보 기재 + 금융조회서(설정 건수)와
대사. 설정일자 상이 병합 건은 Sheet6 에 검토필요로 표시된다.

### 한계 3: 공동담보목록 번호 오매핑 (복잡 PDF)

말소된 순위의 목록번호가 현행 순위에 잘못 붙거나(취소선 유실), 복잡한 다페이지 표에서 블록
격리가 흔들릴 수 있다.
**검증**: 목록번호 연도가 설정 접수일자보다 과거면 의심(예: 2020년 설정에 2019년 목록).
근저당 5건 이상 물건은 원본에서 순위번호별 목록번호를 확인.

### 보정 절차

1. 원본 이미지와 `audit.json`에서 오류의 행·문자 범위·근거를 확인한다.
2. 원본은 보존하고 전사 사본 또는 `review.json`을 수정한다. 전사 사본 변경 시 상세 판독 대장을 새로 준비한다. 취소선 없음 분기의 OCR을 보완해야 하면 사전 판독도 새 입력 해시로 준비한다.
3. `check` → 새 출력 접두사로 파싱 → 필요 시 판단번들·verdict·apply 재실행 → 엑셀 재생성 순서로 진행한다.
4. `*.final.json`을 포함한 결과 JSON 직접 편집은 이미지 증거 무결성 검증에서 차단된다. 파서 결함이면 코드를 수정하고 동일 원본/판독으로 재파싱한다.
