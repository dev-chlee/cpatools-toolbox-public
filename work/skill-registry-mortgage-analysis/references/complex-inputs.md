# 복합 입력 처리

입력 파일명·회사명이 아닌 등기 구조에 따라 처리한다. 원본 PDF/OCR은 보존하고 보완본과
판독 근거를 별도로 남긴다. 파싱 오류가 나면 아래 절차로 원인을 해소한 뒤 다시 실행한다.

## 같은 순위의 여러 근저당

`4번 (1)`, `4번 (2)`는 각각 `4(1)`, `4(2)`로 출력한다. 각 설정의 금액·권리자·채무자·
접수정보를 보존한다. `4번(1)`의 변경·말소는 그 항목에만, 항목 지정 없는 `4번` 말소는
해당 순위 전체에 적용한다. 복수 설정의 변경 대상이 불명확하면 원본에서 항목번호를 확인한다.
접수일·번호·금액이 같다는 이유만으로 서로 다른 항목을 중복 제거하지 않는다.

## OCR이 행을 합치거나 글자를 누락한 경우

먼저 원본 이미지를 열어 행 경계와 전체 셀 내용을 읽는다. `registry_review.extract_units`의
unit ID와 원문 셀을 기준으로 보완 기록을 만든다. 아래 값은 형식 설명용 가상 예시다.

```json
{
  "reviewer": "판독자",
  "corrections": [{
    "unit": "p1-u4",
    "before": ["3 4", "OCR에서 합쳐진 원문"],
    "rows": [["3", "이미지에서 확인한 3번 내용"], ["4", "이미지에서 확인한 4번 내용"]],
    "reason": "원본에서 두 행의 경계와 내용을 대조",
    "evidence": [{"page": 1, "bbox": [0.05, 0.3, 0.95, 0.6], "note": "행 경계"}]
  }]
}
```

```bash
python scripts/registry_inputs.py repair <보관소>/input/source.html <보관소>/output/corrections.json <보관소>/output/repair
```

`repaired.html`과 원본·보완 기록 해시가 포함된 `repair-audit.json`을 생성한다. 보완 전 셀이
다르면 적용하지 않는다. 이 단계에서 취소 내용을 임의 삭제하지 않는다. 보완본을 아래 분리
계획의 `ocr`로 연결하고 상세 판독 대장을 새로 작성하여 취소 범위를 제거한다. 예전 unit ID와
문자 위치를 보완본에 그대로 재사용하지 않는다.

## 여러 물건 또는 비등기 첨부가 포함된 PDF

1. 통상 `registry_image_gate.py prepare`로 모든 원본 페이지 이미지를 준비하고 실제 판독한다.
   각 페이지의 `screening.json`에 `classification`의 종류·사유·이미지 근거를 먼저 채운다.
   비등기 판정 페이지와 아래 `attachments`가 정확히 일치해야 한다.
2. 고유번호·인쇄 쪽수·문서 종류를 확인한다. 고유번호별 분리 후보는 다음 명령으로 얻는다.
   후보 제안은 이미지 판독 완료를 의미하지 않는다.

```bash
python scripts/registry_inputs.py suggest <보관소>/input/source.html
```

3. 원본 물리 페이지 번호로 분리 계획을 작성한다. 다음 예시는 첨부 1쪽과 등기부 2쪽이다.
   여러 물건이면 `parts`에 물건별 항목을 추가한다.

```json
{
  "reviewer": "판독자",
  "reason": "문서 종류와 고유번호를 원본 이미지에서 확인",
  "parts": [{"pages": [2, 3], "ocr": "<보관소>/output/repair/repaired.html"}],
  "attachments": [{
    "page": 1, "kind": "attachment", "reason": "등기부가 아닌 임대차계약서",
    "evidence": [{"page": 1, "bbox": [0.05, 0.05, 0.95, 0.95], "note": "계약서 제목과 본문 확인"}]
  }]
}
```

4. 전체 이미지 확인이 끝난 manifest에 분리 계획을 적용한다. 기존 상세 대장이 있으면
   새 manifest를 준비한다. 모든 경로는 실행 CWD 기준이며 실제 입력 경로를 사용한다.

```bash
python scripts/registry_inputs.py partition <보관소>/output/review/manifest.json source.pdf <보관소>/output/plan.json <보관소>/output/parts
```

물건별 HTML·상세 대장을 만들고 원본 페이지 매핑 및 구조 근거를 manifest에 등록한다.
물건 페이지와 첨부 페이지가 원본 전체를 중복 없이 포함해야 한다. 첨부도 최초 이미지 확인에서
빠뜨리지 않는다. 구조 보완본은 취소선 유무와 관계없이 상세 판독 대상이다.

5. 각 `review.json`에 이미지 판독·취소 범위·독립 기대 결과를 기록한 뒤 기존 파싱 명령에
   `--image-review`를 전달하고 엑셀까지 생성한다. 자세한 명령은 SKILL.md를 따른다.

## OCR에 없는 이미지 페이지

이미지에서 해당 등기부의 모든 내용을 페이지별 HTML로 전사한다. `parts[].ocr`에 전사본을
지정하고 `ocr_is_part: true`를 추가하면 전사본 1쪽부터 `pages`의 원본 쪽에 차례로 연결한다.
전사본과 원본 물건의 쪽수가 같아야 한다. 인쇄 쪽수와 계속 행까지 대조한다.

계약서·중개 설명서의 담보금액으로 등기부 내용을 대신하지 않는다. OCR에 빠졌지만 원본에
있는 페이지는 보완할 수 있다. 원본 자체가 누락되거나 판독 불가하면 추가 원본이 필요하므로
그 사유와 범위를 보고한다. 이런 경우에도 다른 입력 파일의 분석은 계속한다.
